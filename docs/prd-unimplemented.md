# PRD 未实现功能清单

> 对照基准：[`docs/prd.md`](./prd.md) 与当前仓库实现  
> 盘点日期：2026-08-15  
> 本文只记录尚未完成、仅部分完成或仍需产品确认的需求。已经完整实现的功能不在本文展开。

## 1. 当前实现概况

当前已经打通的核心链路包括：

- 项目创建、保存草稿和提交审核
- 项目审核、要求修改、拒绝、上线、下架和恢复上线
- 已上线项目列表和项目详情
- 按项目品类、阶段和关键词筛选
- 点赞和取消点赞
- 关注 Founder、取消关注和关注项目流
- Founder 基础项目管理后台
- 运营项目审核、上线后修改提案审核、审核记录和基础统计
- 项目封面、Demo 图片和 Demo 视频上传
- JWT 登录态、Founder/Operator 角色授权和退出登录

尚未完成的需求主要集中在活动、投票、分享、评论、内测申请、完整数据指标，以及登录和后台管理细节。

待实现内容：

## 3. 部分实现但尚未达到 PRD 要求

### 3.1 登录注册

当前已经实现：

- 验证码发送和校验
- 60 秒重新发送倒计时
- 登录态 Cookie
- 登录后回到来源页面
- 登录后自动恢复点赞和关注动作
- 当前用户信息刷新

与 PRD 的差异：

- 当前使用邮箱验证码，不是中国大陆手机号验证码
- 当前是独立 `/login` 页面，不是居中登录弹窗
- 没有国家/地区码 `+86`
- 没有 11 位手机号和大陆手机号格式校验
- 没有用户协议和隐私政策必选框
- 没有同一手机号每小时最多发送 5 次的前端状态
- 没有连续输错 5 次后锁定设备 1 小时的前端状态
- 没有 PRD 规定的网络异常、服务异常和账号封禁提示闭环
- 目前只支持登录后恢复点赞和关注，尚不支持投票、评论、内测申请等动作恢复

需要先确认：手机号弹窗登录是否仍为目标方案，还是已经由外部认证系统的邮箱验证码和 SSO 方案替代。

### 3.2 退出登录

### 3.3 项目提交字段和校验

### 3.4 待审核项目编辑规则

这些功能与 PRD 中的 P0/P1 定义存在冲突，不能仅根据“Out of Scope”永久关闭。需要由产品重新确认版本范围，并同步修改 PRD 或 v1 规格。

### 4.3 其他明确延期内容

- Founder 等级体系
- Founder 历史项目数
- 多 Founder 或协作者机制
- 完整内容版本快照
- 国际化
- 站内和邮件通知

## 6. 建议实施顺序

### 第一阶段：解决范围和规则冲突

1. 确认黑客松、投票、分享、评论和内测申请是否纳入当前版本。
2. 确认登录采用手机号弹窗还是现有邮箱验证码/SSO。
3. 确认待审核项目是否允许编辑。
4. 确认上线项目允许修改的字段范围。
5. 统一 PRD、前端规格和后端规格的版本边界。

### 第二阶段：补齐已有后端能力的前端闭环

1. 实现 Founder 创建上线项目修改提案。
2. 实现 Founder 修改需修改状态的提案。
3. 补齐项目提交字段校验和错误定位。
4. 完善 Founder 后台已有数据的筛选和展示。
5. 完善运营项目列表和审核记录展示。

### 第三阶段：新增相对独立的小功能

1. 实现分享链接复制和降级弹窗。
2. 增加按点赞数排序。
3. 增加是否开放内测筛选和标签。
4. 完善退出登录确认交互。

### 第四阶段：新增完整领域模块

1. 活动和黑客松。
2. 投票和人气榜单。
3. 评论和机器审核。
4. 内测申请和 Founder 管理。
5. 浏览、分享和其他互动指标。
6. 购买、支持、支付和订单。

## 7. 维护规则

- 功能完成后，应从“尚未实现”移动到对应的“当前已经实现”说明，或直接从本文移除。
- 产品决定取消的功能，应标记为“已取消”，并同步修改 `docs/prd.md`。
- 产品决定延期的功能，应注明目标版本，避免同时出现在 P0 和 Out of Scope 中。
- PRD、前端规格和后端规格发生冲突时，以最新确认的产品决策为准，并同步更新三份文档。
- 新增领域模型前，必须同步更新 [`CONTEXT.md`](../CONTEXT.md) 和必要的 ADR。
